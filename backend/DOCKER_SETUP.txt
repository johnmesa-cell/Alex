🚀 CÓMO EJECUTAR DOCKER
═════════════════════════════════════════════════════════════════

PASO 1: Configurar variables de entorno
───────────────────────────────────────
cd backend

# Copiar .env.example a .env (si no existe)
cp .env.example .env

# EN WINDOWS (PowerShell):
copy .env.example .env

# Verificar que .env tiene:
# - DATABASE_URL="postgresql://johndoe:randompassword@db:5432/alexdb?schema=public"
# - JWT_SECRET="alex_super_secret_key_2026"
# - OPENAI_API_KEY="tu-api-key"


PASO 2: Limpiar contenedores anteriores (recomendado)
────────────────────────────────────────────────────
# Ir a la carpeta raíz del proyecto
cd ..

# Detener y eliminar todos los contenedores
docker-compose down -v

# O solo del backend
docker-compose down -v --remove-orphans


PASO 3: Construir e iniciar con Docker
────────────────────────────────────────
cd backend

# Opción A: Construir y ejecutar (recomendado primera vez)
docker-compose up -d --build

# Opción B: Solo ejecutar (si ya está construido)
docker-compose up -d

# Opción C: Forzar reconstrucción
docker-compose up -d --build --force-recreate


PASO 4: Verificar que funciona
────────────────────────────────
# Ver logs en tiempo real
docker-compose logs -f app

# Verificar que ambos contenedores están corriendo
docker-compose ps

# Debería mostrar:
# CONTAINER ID   STATUS
# alex_app       Up X seconds (healthy)
# alex_db        Up X seconds (healthy)


PASO 5: Probar que la API funciona
──────────────────────────────────
# Terminal nueva, ejecutar:
curl -X POST http://localhost:3000/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{
    "nombre": "Test Docker",
    "correo": "docker@test.com",
    "password": "Docker123"
  }'

# Debería obtener un 201 CON respuesta exitosa

❌ RESOLUCIÓN DE PROBLEMAS
═════════════════════════════════════════════════════════════════

ERROR: "Cannot connect to PostgreSQL"
─────────────────────────────────────
Solución:
1. Verifica que .env tiene DATABASE_URL correcto: db:5432 (NO localhost)
2. Ver logs: docker-compose logs db
3. Esperar a que PostgreSQL esté listo (primeros 10-15 segundos)
4. Si persiste: docker-compose down -v && docker-compose up -d --build


ERROR: "module not found: app.js"
─────────────────────────────────
Solución:
1. Verificar que Dockerfile tiene ruta correcta: express-ts-openai/src/services/app.js
2. Reconstruir: docker-compose up -d --build --force-recreate
3. Ver logs: docker-compose logs app


ERROR: Port 3000 ya está en uso
───────────────────────────────
Solución:
# Opción 1: Cambiar puerto en docker-compose.yml
# ports:
#   - "3001:3000"  ← Cambiar primer 3000 a otro puerto

# Opción 2: Matar proceso anterior
# Windows:
netstat -ano | findstr :3000
taskkill /PID <PID> /F

# Linux/Mac:
lsof -i :3000
kill -9 <PID>


ERROR: "Cannot read property 'prisma'"
────────────────────────────────────────
Solución:
1. Asegurar que npm install se ejecutó: docker-compose up -d --build
2. Generar Prisma: docker-compose exec app npx prisma generate
3. Si sigue: docker-compose down -v && docker-compose up -d --build


ERROR: Health check fallando
────────────────────────────
Solución:
Espera más tiempo - los primeros 30 segundos pueden fallar healthchecks
Ver logs: docker-compose logs app
Si persiste después de 1 minuto: revisar los logs de error
